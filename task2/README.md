# Parallel Convex Hull — Preparata–Hong Algorithm

## 1. Описание проекта

Проект представляет собой реализацию алгоритма построения выпуклой оболочки двумерного множества точек на языке C++ с использованием параллельных вычислений OpenMP.

В качестве основного алгоритма используется алгоритм **Preparata–Hong**, основанный на подходе «разделяй и властвуй» (Divide and Conquer).

Программа получает набор точек на плоскости, вычисляет их выпуклую оболочку и выводит координаты её вершин.

Дополнительно реализованы:

- параллельное выполнение рекурсивных подзадач с использованием OpenMP;
    
- проверка корректности результатов;
    
- визуализация исходного множества точек и построенной выпуклой оболочки;
    
- измерение производительности при различном количестве потоков.

## 4. Алгоритм Preparata–Hong

Алгоритм использует рекурсивный подход «разделяй и властвуй».

Основные этапы:

1. **Сортировка.** Исходные точки сортируются по координате X, а при равенстве X — по координате Y.
    
2. **Разделение.** Множество делится на две части примерно одинакового размера вертикальной прямой.
    
3. **Рекурсивное построение.** Для каждой части отдельно вычисляется выпуклая оболочка.
    
4. **Объединение.** Две полученные оболочки объединяются посредством поиска верхней и нижней общих касательных.
    
5. **Формирование результата.** На основе найденных касательных формируется итоговая выпуклая оболочка.
    

Для небольших наборов точек используется базовый алгоритм построения оболочки.

В реализации предусмотрена обработка вырожденных случаев, а также резервное построение оболочки, если поиск касательных не дал корректного результата.

## 5. Параллелизация

Параллельное выполнение реализовано с помощью OpenMP.

При рекурсивном разделении множества на две части вычисление оболочек для левой и правой частей может выполняться независимо.

Для этого используются:

- `#pragma omp task` — создание параллельных задач;
    
- `#pragma omp taskwait` — ожидание завершения задач;
    
- `#pragma omp parallel` — создание параллельной области;
    
- `#pragma omp single` — запуск начального рекурсивного вызова.
    

Для небольших подмножеств используется последовательное выполнение, чтобы избежать избыточных накладных расходов на создание задач.

Порог перехода к параллельному выполнению в текущей реализации составляет 4096 точек.

Количество потоков задаётся переменной окружения `OMP_NUM_THREADS`.

## 7. Сборка проекта

Из корневой директории проекта выполните:

```
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build -j
```

После успешной сборки исполняемый файл будет находиться по пути:

```
build/convex_hull
```

## 8. Запуск программы

Программа получает входные данные через стандартный ввод.

Формат входных данных:

```
N
x1 y1
x2 y2
...
xN yN
```

Где:

- `N` — количество исходных точек;
    
- `xi`, `yi` — координаты очередной точки.
    

Пример:

```
5
0 0
0 2
2 0
2 2
1 1
```

Запуск:

```
./build/convex_hull < input.txt
```

Количество потоков можно задать следующим образом:

```
OMP_NUM_THREADS=4 ./build/convex_hull < input.txt
```

Результат содержит количество вершин выпуклой оболочки и координаты этих вершин.

## 9. Тестирование

Для проверки корректности реализован отдельный набор тестов.

### 9.1. Проверка корректности

Запуск:

```
python3 tests/validate.py
```

Проверяются:

- множества из одной и двух точек;
    
- треугольники и прямоугольники;
    
- внутренние точки;
    
- коллинеарные точки;
    
- точки с одинаковыми координатами X или Y;
    
- случайно сгенерированные наборы точек различного размера.
    

Результаты сравниваются с независимой реализацией алгоритма построения выпуклой оболочки.

В ходе тестирования успешно пройдены **148 проверок**.

### 9.2. Проверка параллельного выполнения

Запуск:

```
python3 tests/parallel_test.py
```

Проверяется совпадение результатов при использовании 1, 2, 4 и 8 потоков.

На тестовом наборе из 100 000 случайных точек результаты всех запусков совпали.

## 11. Эксперименты производительности

Для оценки производительности программа тестировалась на наборах размером от 10 000 до 1 000 000 точек.

Использовалось 1, 2, 4 и 8 потоков. Для каждого сочетания размера набора и количества потоков выполнялось три запуска, после чего вычислялось среднее время выполнения.

Запуск эксперимента:

```
python3 tests/benchmark.py
```

Результаты сохраняются в:

```
results/benchmark_results.csv
```

Для построения графиков:

```
python3 tests/plot_benchmark.py
```

Создаются три графика:

- `results/benchmark_time.png` — зависимость времени выполнения от количества потоков;
    
- `results/benchmark_speedup.png` — ускорение параллельной реализации;
    
- `results/benchmark_efficiency.png` — эффективность использования потоков.
    

### Результаты экспериментов

Среднее время выполнения (секунды):

|Количество точек|1 поток|2 потока|4 потока|8 потоков|
|---|---|---|---|---|
|10 000|0.0187|0.0152|0.0149|0.0159|
|50 000|0.0571|0.0471|0.0482|0.0455|
|100 000|0.1171|0.0930|0.0910|0.0891|
|500 000|0.8048|0.5728|0.5580|0.5086|
|1 000 000|2.3083|1.5774|1.3896|1.3337|

На наборе из 1 000 000 точек ускорение при использовании 8 потоков составило приблизительно **1.73 раза** относительно последовательного выполнения.

Эксперименты показывают, что параллельное выполнение позволяет сократить время вычислений. При увеличении размера входного набора преимущество многопоточной реализации становится заметнее.
